1. Introduction & the three kinds of analytics

Source: Handout 0 — Introduction to Modeling

Management science / operations research (OR/MS)

  • Interdisciplinary study of problem solving and decision making in organizations, using mathematical modeling, statistics and numerical algorithms to reach optimal or near-optimal decisions. “Management science” and “operations research” are used interchangeably.
  • First used by the military in WWII to allocate scarce resources; moved into business, industry and government by the early 1950s.
  • What sparked its growth: better theory (e.g., the simplex method) and computers (making large problems tractable, sometimes).
  • Solver software: Excel, LINDO, CPLEX, GUROBI, Matlab, R and others. This course uses Excel, Gurobi and R.

Descriptive vs. predictive vs. prescriptive

TypeWhat it doesTypical tools
DescriptiveWhat happened / is happening? Visualization-heavy, a.k.a. business intelligence (BI).Dashboards, monitoring
PredictiveWhat will happen? Forecasts future performance.Statistical and machine-learning models
PrescriptiveWhat should we do? Recommends decisions.Mathematical and simulation-based models (optimization)

This course is prescriptive analytics, the main focus of OR/MS. Running example in the slides: a wastewater plant. Sensors monitoring it are descriptive; a model of the aeration process is predictive; optimizing the aeration settings is prescriptive.

Building blocks of any prescriptive model

  1. Decisions (what we control).
  2. Constraints on how decisions can be made (if any).
  3. A performance measure that scores a decision; this defines the objective function.
  4. Goal: find an optimal solution, i.e., maximize or minimize the objective function.
Questions prescriptive analytics asks

Is there only one solution? What is a “good” or “best” one, with respect to what (the performance measure)? Are there constraints on the decisions?

Applications shown: supply chain management, advancing cancer therapeutics, scheduling softball in Ohio, portfolio optimization.

2. Complexity & algorithm analysis

Source: Complexity and Algorithm Analysis slides · Assignment 1, Q1

Why it matters

  • Complex systems have many interconnected parts; complexity becomes quantifiable once a measure for component relationships is chosen.
  • For a problem on a network (subgraph detection, paths, centrality, …) we ask whether our algorithm can solve it in reasonable time.
  • Intractable problem → no optimal solution in reasonable time → use an approximation or heuristic algorithm. Tractable → an efficient optimal algorithm exists; find the fastest one.
  • Goals of complexity analysis: quantify problem difficulty, compare problem classes, define “efficient”, compare algorithms for the same problem.

Measuring running time

  • Wall-clock time depends on the computer, so we count primitive operations as a function of input size (n, m, e.g., nodes and arcs). This is platform-independent.
  • Best case gives no guarantee; average case needs probabilities; worst case gives a guarantee and is easiest to analyze — we use it.
  • Model of computation: sequential machine; infinite memory; each simple instruction (arithmetic, comparison, assignment, load/store/copy, subroutine call/return) takes 1 step; ignore constants.
Big-O

O(·) is the worst-case running time of an algorithm. Keep the dominant term, drop constants:

  • am + bn operations → O(m+n)
  • 3mn + m operations → O(mn)
  • kn3 + m operations → O(n3) as written on the slide (strictly O(n3+m) if m is independent of n)

Polynomial O(nc) = “good”/efficient. Exponential O(2n) = “bad”. Brute force (check every solution) is typically 2n or worse: unacceptable in practice.

Basic graph algorithms

  • BFS: explore nodes in order of “distance” from the source s, using a queue. Every vertex is enqueued at most once (O(|V|)); an edge is examined only when its tail is dequeued, so at most once if directed, twice if undirected (O(|E|)). Total O(|V|+|E|).
  • DFS: go as far as possible from each newly discovered node, then backtrack (BFS instead queues nodes to explore later). Each node visited once, each edge crossed once: O(|V|+|E|).

Problem classes: P, NP, NP-complete

  • P: solvable in polynomial time.
  • NP: a proposed solution can be verified in polynomial time.
  • NPC (NP-complete): the “hard” problems in NP; believed not solvable in polynomial time.
  • To show a problem is NPC, transform a known NPC problem into it. If any NPC problem were solved in polynomial time, all would be.
  • Open question: does P = NP?
Self-check
  1. Why do we analyze the worst case rather than best or average?
    Worst case gives a guarantee and is easier to analyze; best case says nothing about difficulty and average case depends on assumed probabilities.
  2. Simplify: (a) 5m + 2n + 7; (b) 4n3 + 100n2; (c) two nested loops over n nodes followed by one loop over m edges.
    (a) O(m+n); (b) O(n3); (c) O(n2+m).
  3. What is the running time of BFS and what makes up each term?
    O(|V|+|E|): |V| for enqueuing each vertex once, |E| for examining each edge at most once (twice if undirected).
  4. True/false: any problem in NP is not solvable in polynomial time.
    False. P is inside NP, so some NP problems are polynomial. Only the NP-complete ones are believed not to be.
  5. Is an O(2n) algorithm considered efficient?
    No. Efficient means polynomial; exponential is the “bad” case.

Source: Handout 01 (1 of 2) · Assignment 3, Part I review questions

Three ways to solve an optimization model

SoftwareTranslate the model into a solverLimits of the tool (Excel cannot handle large IPs)Almost any real problem

The general optimization model

max f(x1,…,xn)   s.t.   gi(x1,…,xn)  (≤, = or ≥)  0,   i = 1,…,m
  • Objective function f: has a sense (min or max); the optimal value is unique but the optimal solution may not be.
  • Naming: use subscripts — xi (single) or xij (double).
  • Unconstrained = no constraints; constrained = at least one.
  • Variable types: continuous, integer, binary (0 or 1), free (any value), non-positive, non-negative.
  • Constraint types are ≤, ≥, =. Strict < or > are avoided because we might not obtain a min or max (e.g., min x s.t. x > 0 has no minimum).
  • Min ↔ max: max f(x) is the same as −min(−f(x)); min f(x) is the same as −max(−f(x)).
  • The types of f and gi (linear, nonlinear, piecewise linear, convex, nonconvex) determine the type of problem and its difficulty.
Vocabulary (from Assignment 3 review)
  • Model: captures some but not all characteristics of the real decision (true).
  • Objective function: evaluates the quality/value of a solution.
  • Constraint: a limitation on how decisions can be made.
  • Decision variable: what we choose. Continuous e.g. gallons of paint; integer e.g. number of trucks; binary e.g. open a warehouse (1) or not (0).
Self-check
  1. Rewrite “min 3x1 − x2” as a max problem. How do you recover the original value?
    max −3x1 + x2. Original optimal value = −(max value).
  2. Why can’t we use < or > in constraints?
    The optimum may not exist (the feasible set has no boundary point to attain), so a minimum or maximum might not be obtained.
  3. Which solution approach only works if the set of solutions is finite?
    Enumeration (integer problems).

4. Unconstrained optimization & the fencing problem

Source: Handout 01 (2 of 2) · Assignment 1, Q2–Q3

Unconstrained optimization

Find a min or max with no constraints; variables take any value. In calculus you did this by setting the derivative to zero. Other methods:

  • Derivative-free: dichotomous search, Fibonacci search, golden-section search.
  • Derivative-based: gradient descent, Newton’s method.

Gradient descent (GD)

Idea

An iterative algorithm to minimize a differentiable function by stepping in the direction where it decreases fastest. The gradient ∇f points where f increases fastest (in 1-D, just the derivative), so we move along the negative gradient.

  1. Start at some initial point.
  2. Compute the gradient there.
  3. Step opposite the gradient: x ← x − η ∇f(x).
  4. Repeat until the function stops decreasing significantly.

η is the learning rate (step size).

Stochastic gradient descent (SGD)

  • A variant of GD for large datasets (typical in machine learning). GD uses the gradient over the entire dataset; SGD approximates it from one example or a small random mini-batch each iteration, which is “noisy” but faster.
  • Update rule: θ ← θ − η ∇ℒ(θ; xi, yi) where (xi,yi) is a randomly chosen data point.
Advantages
  • Efficient for large data.
  • Faster convergence: noise can help escape local minima in non-convex landscapes.
  • Online learning: handles streaming data.
Disadvantages
  • Noisy updates: zig-zag path, slower convergence to the exact minimum.
  • Learning-rate sensitivity: too high → divergence; too low → stalls.

Considerations for GD and SGD

  • Learning rate η: too small → slow (many tiny steps); too large → overshoot/oscillate (e.g., η = 0.2 might jump past the minimum). Balancing act, tuned experimentally.
  • Convergence: for convex functions (e.g., MSE in linear regression) GD finds the global minimum. For non-convex functions (neural networks) it may stop at a local minimum, where SGD can do better.
  • Neural networks: loss depends on many weights/biases; use backpropagation to compute all gradients, then update each parameter with GD/SGD.

The fencing problem (first constrained example)

Problem

A farmer has 2400 ft of fencing and wants a rectangular field bordering a straight river. No fence is needed along the river. What dimensions give the largest area?

(The model slide was blank in class; this is the standard formulation, check against your notes.) Let x = length of each of the two sides perpendicular to the river and y = the side parallel to it.

max xy   s.t.   2x + y ≤ 2400,   x, y ≥ 0

Use all the fence: y = 2400 − 2x, so area A(x) = 2400x − 2x2. Then A′ = 2400 − 4x = 0 ⇒ x = 600, y = 1200, area = 720,000 ft².

Is it an LP?

No. The objective xy is a product of variables (nonlinear), so the fencing problem is not a linear program, even though its constraints are linear. The Diet and Wyndor problems are LPs (Chapter 6).

    SGD uses one example/mini-batch per step instead of the full dataset: cheaper steps and can escape local minima, but noisier, zig-zagging updates.

5. Linear programs: general, standard & matrix form

Source: Handout 02 · Assignment 3, Q6–Q7

General form

General form of an LP

Continuous decision variables x1,…,xn.

max (or min)   c1x1 + … + cnxn
s.t.   ai1x1 + … + ainxn  (≤, = or ≥)  bi,   i = 1,…,m
xj ≥ 0, ≤ 0, or free

Standard form

Standard form (this course)
min   ∑j cjxj    s.t.   ∑j aijxj ≥ bi  (i = 1,…,m),    xj ≥ 0  (j = 1,…,n)

i.e., objective is min, every constraint is ≥, every variable is non-negative. (“One example of a standard form” per the slide.)

Conversion rules

To fix…Do this
max fmin −f (and negate the final value)
constraint a·x ≤ bmultiply both sides by −1: −a·x ≥ −b
constraint a·x = breplace with two: a·x ≥ b and a·x ≤ b (then flip the ≤ as above)
variable xj ≤ 0substitute xj = −xj′ with xj′ ≥ 0
free variable xjxj = xj+ − xj− with both ≥ 0
constants on the left of a constraintmove them to the right-hand side first

Why only min? Because max converts to min. Why only ≥ and x ≥ 0? Because you can always convert between ≤ and ≥, and between “free” and ≥ 0.

Matrix form

Matrix form
min   cTx    s.t.   Ax (≤, = or ≥) b,    x (≥ 0, ≤ 0 or free)
  • cT = [c1,…,cn]: objective coefficients (1×n).
  • x = column of n decision variables.
  • A = m×n matrix of constraint coefficients (row = constraint, column = variable).
  • b = column of m right-hand sides.

Matrix operations you need: transpose of a vector; cTx (a single number: the objective value); Ax (a vector: the left-hand side of every constraint).

Recipe for formulating an LP

  1. Define the decision variables in words, with units.
  2. Write the objective (sum of contribution × variable).
  3. Write each constraint (resource used ≤ available; requirement met ≥ minimum).
  4. State variable sign restrictions.
  5. Check units of the objective and of each constraint (Assignment 3 asks you to demonstrate this).

7. The graphical solution method

Source: Handout 03 · for LPs with two decision variables

Steps

  1. Draw each constraint boundary line. Test the origin (or any point off the line) to see which side is allowed.
  2. Feasible region = where all constraints hold simultaneously (include x1,x2 ≥ 0).
  3. Find the slope of one objective (iso-profit / iso-cost) line; all others are parallel.
  4. Slide a straight edge with that slope through the region in the direction of improving objective value (up for max, down for min). Stop at the last instant it still touches the region: the optimal objective line.
  5. A feasible point on that line is an optimal solution. Read off the coordinates and compute the objective value.

For the grader (Assignment 3 Q11): show the feasible region, at least two iso-lines including the optimal one, the optimal solution and the optimal objective value.

Key observations about corner points & binding constraints (standard results)

  • If an LP has an optimal solution, at least one optimal solution is at a corner point (extreme point). So it is enough to compare the corner points.
  • With several optimal solutions, at least two adjacent corners are optimal, and every point on the segment between them is too.
  • A binding constraint holds with equality at the solution; a non-binding one has slack. In two variables, a corner is where two binding constraints intersect.
  • Wyndor at (2, 6): plant 2 (2·6 = 12) and plant 3 (3·2 + 2·6 = 18) are binding; plant 1 has slack (2 < 4).

The three “what if” questions on Wyndor

A. Are there multiple optimal solutions in the original problem?

No. The objective line slope (−3/5) is not parallel to any constraint edge, so it touches the region at the single corner (2, 6).

B. What if profit per batch of Product 2 were $2,000?

The objective becomes 3x1 + 2x2, whose iso-lines have slope −3/2, parallel to the Plant 3 constraint 3x1 + 2x2 = 18. Every point on the segment from (2, 6) to (4, 3) is optimal with Z = 18. Not unique: multiple optimal solutions.

C. What if we add the constraint 3x1 + 5x2 ≥ 50?

The slide requires points above that line, while the original region lies below it (its maximum of 3x1+5x2 is 36 < 50). No point satisfies everything: the problem becomes infeasible.

Watch out
  • For a min problem, slide the iso-line in the direction that decreases the objective, and stop at the first feasible point it reaches.
  • Always shade the correct side of each constraint, and check with the origin.
  • Equality constraints (as in Assignment 3, Q10) restrict you to the line itself, not one side of it.
  • Report both the optimal solution (the point) and the optimal objective value.

    If it equals the slope of a binding constraint edge at the optimal end of the region, the whole edge is optimal.

8. One-page cheat sheet

Analytics & modeling

  • Descriptive (what happened) → predictive (what will happen) → prescriptive (what to do).
  • Model = decisions + constraints + objective.
  • Variable types: continuous, integer, binary, free, ≥0, ≤0.
  • max f = −min(−f).

Complexity

  • Worst case, count primitive steps, drop constants.
  • Loops: multiply their own bounds. n×m×p → O(nmp).
  • Poly = efficient; 2n = brute force.
  • BFS, DFS: O(|V|+|E|).
  • P ⊂ NP; NPC believed outside P; P = NP open.

Gradient descent

  • x ← x − η ∇f(x). Update all variables together, recompute f unrounded.
  • η too big → oscillate; too small → slow.
  • Convex → global min. SGD = one sample/mini-batch per step.
  • f = x2+2y2: ∇f = (2x, 4y).

LP standard form

  • min, all ≥, all x ≥ 0.
  • ≤ → multiply by −1. = → two inequalities. Free → x+−x−. ≤0 var → negate.
  • Matrix: min cTx s.t. Ax ≥ b, x ≥ 0. Constants go to the RHS first.

LP assumptions

Proportionality, additivity, divisibility, certainty.

Graphical method

  1. Draw constraints, test origin.
  2. Shade the feasible region.
  3. Draw iso-lines (same slope).
  4. Slide to the last touch (max: up/right; min: down/left).
  5. Solve the two binding lines for the optimum.

Outcomes

Unique · multiple (iso-line parallel to an edge) · unbounded · infeasible. Optimal solutions are at corner points.
